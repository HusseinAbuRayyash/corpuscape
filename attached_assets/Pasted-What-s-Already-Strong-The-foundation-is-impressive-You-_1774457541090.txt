What's Already Strong
The foundation is impressive. You're using a modern stack (React + Tailwind + Recharts + shadcn/ui), the design system is cohesive with a beautiful teal-to-indigo gradient palette, and you have both light and dark mode with well-thought-out CSS variables. The glassmorphism cards, polished hover effects (metric-card, track-card, polished-card), and custom animations (fade-in-up, pulse-glow, float) give it a premium feel. The feature depth — 31 AI analysis types, 40+ color palettes, 12 chart types, TMX export — is exceptional for a free tool.

UX Recommendations
1. Onboarding & First-Time Experience
The app drops users directly into the interface with no guided introduction. For a workshop tool targeting researchers who may not be tech-savvy, consider adding an interactive first-run tour (something like react-joyride) that walks through the five tracks with 4–5 tooltip steps. A "Try with sample data" button on each track's empty state would also dramatically lower the barrier to entry — participants could see results instantly before uploading their own data.
2. Navigation & Wayfinding
You have 6 routes (/, /monolingual, /bilingual, /scraper, /compare, /figures) but from the JS I can see there's no breadcrumb or progress indicator once a user is deep in an analysis workflow. When someone uploads a corpus, runs filters, then launches AI analysis, they need a sense of where they are. Consider a lightweight stepper or breadcrumb trail at the top of each track: Upload → Clean → Analyze → Export.
3. Cross-Track Workflow Integration
The tracks are currently siloed. A user who scrapes a corpus in the Scraper track and wants to analyze it in the Monolingual track has to re-upload. Adding a "Send to Monolingual Track" or "Send to Figure Maker" button after scraping or analysis would create a fluid pipeline that matches how researchers actually work — they don't think in tracks, they think in workflows.
4. Error States & AI Feedback
I can see you have error messages like "AI couldn't generate quantifiable data for this prompt" and "Try a clearer format or include numbers." These are good, but consider making them more actionable with concrete examples: "Try: 'List the top 10 most frequent translation strategies and their counts' instead of vague prompts." The empty-state styling (dashed border, gradient background) is elegant but could include a short animated illustration or icon to feel less sterile.
5. Export Workflow
You support Word, PDF, PNG, CSV, and TMX export — that's great. But the export controls seem scattered across different parts of the interface. Consider consolidating exports into a unified "Export" panel or drawer that shows all available formats for the current view, with format-specific options (resolution for PNG, citation style for reports, etc.) in one place.

UI Recommendations
6. Font Loading Performance
You're loading 25+ Google Font families in a single <link> tag — Architects Daughter, DM Sans, Fira Code, Geist, IBM Plex, Inter, JetBrains Mono, Libre Baskerville, Lora, Merriweather, Montserrat, Open Sans, Outfit, Oxanium, Playfair Display, Poppins, Roboto, Source Code Pro, Source Serif, Space Grotesk, Space Mono, and more. This is a significant performance hit on initial load. Since these are mostly for the Figure Maker's font options, load them lazily only when the user enters the Figure Maker track, not on every page load.
7. Landing Page Hero
The title text uses a text-gradient (teal → indigo → purple) which is beautiful, but the .hero-gradient background is extremely subtle (0f / 6% opacity). For a workshop tool that needs to immediately communicate what it does, consider making the hero section more visually assertive — perhaps a brief animated demo or a screenshot carousel showing real outputs (a concordance table, a publication-ready chart, aligned bilingual text).
8. Sidebar Design
The dark sidebar (224 30% 12% — a deep navy) with teal accents is clean and professional. However, the sidebar width appears fixed. For the analysis-heavy tracks where users need maximum horizontal space (concordance views, wide tables), consider making the sidebar collapsible to icon-only mode, or auto-collapsing on smaller screens.
9. Data Table Readability
The .polished-table styles use 0.7rem uppercase headers with 0.05em letter-spacing, which is elegant but may strain readability for large datasets. For corpus researchers scrolling through hundreds of concordance lines or frequency tables, consider slightly larger headers (0.75rem), alternating row backgrounds, and sticky header rows.
10. Chart Preview in Figure Maker
You support 12 chart types (bar, horizontal bar, stacked bar, line, area, pie, donut, half-donut, radar, scatter, funnel, treemap) with 40+ palettes. This is a lot of options. Consider adding a live thumbnail preview grid when selecting chart type — showing the user's actual data rendered in each chart type as small thumbnails so they can visually compare before committing. Similarly, palette selection would benefit from a preview swatch that applies to the current chart, not just a color strip.
11. Mobile Responsiveness
Your CSS breakpoints (sm: 640px, md: 768px, lg: 1024px) are standard, but I see many md:hidden and md:flex toggles suggesting the mobile experience may be limited. For the workshop specifically, some participants will be on tablets. Ensure the upload zones, filter panels, and chart views are usable at 768px width.
12. Accessibility
The selection color (#1abc9c33 / teal at 20% opacity) is lovely, but some of the muted-foreground text at .4 or .5 opacity on the light background may not meet WCAG AA contrast ratios. Run the muted-foreground values (particularly hsl(220 12% 32%) on the light theme) through a contrast checker against your background and card colors. Also, ensure all interactive elements in analysis panels have visible focus indicators — the current focus-visible ring is good but might get lost on some of the more complex card layouts.

Quick Wins for the Workshop Specifically
Consider adding a /workshop or /demo mode that pre-loads the sample datasets I created, disables the API key requirement (if any), and shows helpful tooltips explaining each feature as participants explore. This would make the live demo portion much smoother and reduce setup friction to zero.
